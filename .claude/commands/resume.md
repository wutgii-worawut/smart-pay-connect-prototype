คุณคือ main agent ของ session ใหม่ ทำตามลำดับ:

1. **Bootstrap**: อ่าน `plan/progress.md` ทั้งไฟล์ (โดยเฉพาะข้อ 1 และ "บันทึกแก้แผน" ท้ายไฟล์)
   แล้วอ่าน `plan/plan.md` เฉพาะเฟสที่จะทำ ($ARGUMENTS ถ้าระบุ, ไม่งั้นใช้ "งานถัดไป" ใน 1.2)
   + feature plan (`docs/feature-plans/`) ที่เฟสนั้นอ้าง — อย่าอ่านทุกอย่างเกินจำเป็น ประหยัด context
   - **ถ้าผู้ใช้ระบุเฟสเอง ให้เช็ค dependency ก่อน**: ดูตารางเฟสใน progress.md —
     ถ้ามีเฟสก่อนหน้าที่เฟสนี้ต้องพึ่ง (ตาม plan.md) ยังไม่ ✅ ให้แจ้งผู้ใช้ตรง ๆ ว่า
     "เฟส X ยังไม่เสร็จ อาจกระทบ..." แล้ว**รอผู้ใช้ยืนยันว่าจะข้ามจริง**ก่อนลงมือ ห้ามตัดสินใจแทน

2. **ยืนยันก่อนเริ่ม**: สรุปสั้น ๆ ให้ผู้ใช้ว่าเข้าใจสถานะปัจจุบันว่าอะไร + จะทำเฟสไหน ขอบเขตอะไร
   แล้ว**รอผู้ใช้เคาะก่อนลงมือ**

3. **ทำงานตามบทบาท** (progress.md ข้อ 1.4):
   - อัปเดตสถานะเฟสเป็น 🔄 → มอบงานให้ subagent `worker` พร้อม spec จากเฟสนั้น
     (ระบุไฟล์ feature plan + รูป design ที่เกี่ยว)
   - worker เสร็จ → อัปเดตเป็น 🔍 → ส่ง subagent `consultant` รีวิว diff/ไฟล์ที่แตะ
   - follow-up จาก consultant → ให้ worker แก้จนเคลียร์
   - main agent verify เอง: `npm run lint` → `npx tsc --noEmit` → `npm run test` → `npm run build`

4. **ปิดเฟส**: อัปเดต `plan/progress.md` — สถานะปัจจุบัน (1.1), งานถัดไป (1.2),
   ตารางเฟส (ยังไม่ mark ✅ จนกว่าผู้ใช้เคาะ), เพิ่ม "บันทึกแก้แผน" ถ้ามีการเบี่ยงจาก plan.md
   หรือเจอกับดักที่ session หน้าควรรู้

5. **สรุปแล้วหยุด**: รายงานผู้ใช้ — สิ่งที่ทำ, ผล verify, ประเด็นจาก consultant, คำถามค้าง (ถ้ามี)
   แล้ว**หยุดรอผู้ใช้เคาะ** — ผู้ใช้เคาะแล้วจึง mark ✅ ห้ามเริ่มเฟสถัดไปเองเด็ดขาด

6. **หลายเฟสใน session เดียวได้**: ถ้าผู้ใช้เคาะแล้วสั่ง "ไปเฟสถัดไป" ให้ทำต่อใน session นี้ได้เลย
   โดย**วนขั้น 3-5 ครบทุกขั้นเหมือนเดิมทุกเฟส** (worker → consultant รีวิวโค้ดทุกครั้ง →
   follow-up แก้ → main verify → อัปเดต progress.md → สรุป → รอเคาะ) — ห้ามลัดขั้นตอนเพราะอยู่ session เดิม
   และก่อนเริ่มเฟสใหม่ให้ประเมิน context: ถ้าใกล้เต็ม บอกผู้ใช้ตรง ๆ ว่าควรเปิด session ใหม่แล้วค่อย /resume

ข้อห้ามยืนพื้น: ห้ามทำเกินขอบเขตเฟส, ห้ามแตะเรื่องใน Open Questions (architecture.md §23)
โดยไม่ถามผู้ใช้, ถ้า context ใกล้เต็มให้รีบปิดงานที่ค้าง อัปเดต progress.md ให้ครบ แล้วบอกผู้ใช้ให้เปิด session ใหม่
