คุณคือ main agent — ผู้ใช้ต้องการปิด session **เดี๋ยวนี้** งานอาจค้างกลางเฟส ทำตามลำดับ ห้ามเริ่มงานใหม่:

1. **หยุดงานที่กำลังทำทันที** — ถ้า worker/consultant กำลังรันอยู่ ให้รอผลรอบปัจจุบันจบ
   แล้วไม่มอบงานเพิ่ม ห้ามพยายาม "ทำอีกนิดให้จบเฟส"

2. **เช็คสภาพโค้ดที่ค้าง** (อ่านอย่างเดียว ห้ามแก้เพิ่ม):
   - `git status` + `git diff --stat` — ไฟล์ไหนถูกแตะบ้าง
   - รัน `npm run lint` และ `npx tsc --noEmit` เพื่อรู้ว่าสภาพปัจจุบัน "เขียว" หรือ "แดง"
     (แดงไม่ต้องแก้ — แค่บันทึกว่าแดงตรงไหน)

3. **อัปเดต `plan/progress.md` ให้ละเอียดกว่าปกติ** เพราะ session หน้าไม่มี context นี้แล้ว:
   - **1.1 สถานะปัจจุบัน**: เฟสที่ค้าง + ทำไปถึงไหน — ระบุเป็นรายการไฟล์:
     "เสร็จแล้ว: ...", "ค้างกลางคัน: <ไฟล์> เพราะ <อะไร>", "ยังไม่เริ่ม: ..."
     + ผล lint/tsc ล่าสุด (เขียว/แดงตรงไหน) + follow-up ของ consultant ที่ยังไม่ได้แก้ (ถ้ามี)
   - **1.2 งานถัดไป**: ขั้นแรกที่ session ใหม่ต้องทำต่อแบบสั่งได้ทันที
     (เช่น "แก้ type error ใน LeaveForm.tsx:42 ก่อน แล้วต่อข้อ 3 ของเฟส 4")
   - **ตารางเฟส**: เฟสค้างคงสถานะ 🔄 (ห้าม mark ✅ — ผู้ใช้ยังไม่เคาะ)
   - **บันทึกแก้แผน**: ถ้ามีการตัดสินใจ/กับดัก/ทางที่ลองแล้วไม่เวิร์คใน session นี้ ให้จดไว้กันทำซ้ำ

4. **เสนอ commit งานค้าง** (ถามผู้ใช้ก่อน ไม่ทำเอง): แนะนำ commit เป็น WIP
   เช่น `wip(phase-4): LeaveForm ค้าง validation` เพื่อไม่ให้งานหายและ diff อ่านง่ายใน session หน้า
   — ถ้าผู้ใช้ไม่ตอบ/ปฏิเสธ ปล่อยไว้เป็น uncommitted ได้ แค่ระบุใน progress.md ว่ายังไม่ commit

5. **สรุปปิดท้ายสั้น ๆ**: บอกผู้ใช้ — ทำอะไรไปบ้างใน session นี้, ค้างอะไร, ผล lint/tsc,
   และยืนยันว่า session ใหม่แค่พิมพ์ `/resume` ก็ทำต่อได้เลย แล้วจบ ไม่ต้องถามอะไรต่อ
